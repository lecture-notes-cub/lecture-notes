
M2 is worth 20 points, one fifth (1/5) of your total grade. You get one grade per team. Deadline: Mon 26.10.2026, 23:59. Late submissions receive at most 50% of the points (only commits pushed to main before the deadline are graded).

This is a building milestone. We want to see the loop working end-to-end and first honest numbers on how well it works. It is GREAT to find problems at this point. A working agent with well diagnosed failures scores higher than a polished demo nobody measured!

You don't have that much time. Use it wisely. You don't need a state-of-art agent at this point. Focus on neat, workable harness. Start small. Add one thing at a time, document it, add another thing. You can mock tools and use static data for the sake of time for now.

What will be graded?

Working agent (5 pt). Your agent runs end-to-end on tasks from your domain from one documented entry point. It has to be a real agent loop: the model chooses the next action (which tool, with which arguments) and decides when to stop. A fixed pipeline where code decides every step does not count as the agent (but you might want to start with that).

You agent should handle at least one class of error (instead of crashing): a tool error or timeout, an empty result, etc. If anything changed since M1 (model, tools, scope), say what and why.

Tracing (5 pt). Every run should leave a structured log that covers every step: model call, tool call, arguments, observation, final answer, etc. At every step where the model decides something, log the decision. A third party should be able to rebuild what the agent decided and why from the log alone.

First evaluation (5 pt). You run an evaluation on a frozen sample of at least 20 tasks, chosen to represent what the agent will actually see. Commit the sample (and, if possible, a frozen copy of the environment: saved pages, files, API responses) to the repo: this exact sample will be used to compare your variants in M3.

Method. Pick what fits your task, preferably try two. Explain why it fits your task.
Levels. Say what you evaluate: only the final answer (task level), or also the path (selection, arguments, trajectory). Justify the choice.
Cost of the result. Report next to the success numbers: steps and calls per task, $ and latency per task.
Baseline. Run your Stage 0 workflow (or one LLM call with no loop) on the same sample. This shows whether the agent loop actually earns its cost, and you will need it in M3 anyway.
Report the results honestly, including where the evaluation itself is uncertain. Connect it to your M1 eval plan: what you kept, what you changed, and why.

First failure analysis (5 pt). At least 3 annotated runs where something went wrong. For each one, name the problem, point to the exact step and decision in the trace, and propose a plausible root cause (model output, tool return, prompt, planning, context handling?). Keep these traces in the repo: in M3 each of them becomes a unit test for a decision (freeze the prefix, stub the tools, ask "what is the next action?"). Update your M1 failure map: which predicted failures did you actually see?

Deliverables

Code in your repo: the agent, the eval script and the eval sample.
Documentation (README or M2.md): how to run the agent, how to run the eval, the results, and the failure analysis with links to the trace files.
Reproducibility:

Cloud / API models: the README must let me run the agent and the eval on my machine: dependencies, env variables (no real keys in the repo PLEASE!!!), the exact commands, and the expected output. If I can't run it from your instructions, Working loop can't get full points.

Local models: If you choose to work with local model, record a screen video (3–5 min) of the agent working on 2–3 tasks from your eval sample with your voiceover, with the trace being written. Link it in the README (you can use Google Drive or similar tool). Also include the model name, size, quantization etc so the setup is documented. Commit sample traces from your eval run to the repo.
